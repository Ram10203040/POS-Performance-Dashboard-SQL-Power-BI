# Life Insurance POS Practice Dataset (3 months, synthetic)

All data is **synthetic**, generated by `generate_pos_data.py` (fixed seed, reproducible). No real customers or policies.
If you use it in a portfolio or interview, say so: "synthetic POS data created for practice."

## Files
| File | Purpose |
|---|---|
| `create_and_load_pos_3m.sql` | Creates database `insurance_pos_3m`, the 4 tables, and loads all data (MySQL 8.0+) |
| `customer.csv`, `policy.csv`, `pos_request.csv`, `premium_payment.csv` | Same data as CSV for Excel / Power BI / MySQL import |
| `practice_queries_3m.sql` | 21 practice queries (16 analysis + 5 data-quality checks) |
| `generate_pos_data.py` | The generator (publish it on GitHub with the project) |

## How to load
**MySQL:** open `create_and_load_pos_3m.sql` in MySQL Workbench and run it once (it drops and recreates the database). Or: `mysql -u root -p < create_and_load_pos_3m.sql`.
**Excel / Power BI:** use Data > From Text/CSV on each CSV. Blank cells are NULLs. If dates come in as text, use Text to Columns with Date: YMD.
Tested on MariaDB 10.11 (MySQL-compatible). Window functions and CTEs need MySQL 8.0 or later.

## Tables and row counts
| Table | Rows | Notes |
|---|---|---|
| customer | 2,000 | dob 1950-2000, 20 cities |
| policy | 3,000 | 5 plans; status mix: In Force ~70%, Lapsed, Paid-up, Surrendered, Matured |
| pos_request | 6,025 | 6,000 requests received 1 Jul - 30 Sep 2026, plus 25 planted duplicates |
| premium_payment | 5,848 | installments due 1 Apr - 30 Sep 2026 (In Force and Lapsed policies) |

Key columns: `pos_request.status` = Closed / Pending / Rejected; `stp_flag` Y = straight-through, N = manual touch; `closed_date` is NULL while Pending; `reject_reason` is filled only when Rejected; `premium_payment.paid_date` NULL = unpaid.
**Aging "today" = 30 Sep 2026** (use `'2026-09-30'`, not `CURDATE()`).

## Patterns planted in the data (so your analysis finds a story)
- STP improves each month (23% -> 27% -> 33%).
- Portal and Mobile App have much higher STP than Branch and Distributor.
- Revival, Surrender and Policy Loan are slow; Contact Update is fast.
- Volume is lower on weekends, with a spike at month-end and a dip on 15 Aug.
- "Policy not in force" is the top rejection reason (requests on lapsed, surrendered or matured policies).
- Lapsed policies account for most unpaid premiums.
